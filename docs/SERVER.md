# Сервер «Учёт SIM» на своём VPS

Сервер хранит карточки SIM и фото паспортов **только в зашифрованном виде**. Расшифровать их можно
на телефоне или в браузере после ввода мастер-пароля. Подробно — в [SECURITY.md](SECURITY.md).

## Что нужно

- VPS на Linux (x86-64 или ARM) с systemd и **Caddy, установленным как системная служба** (`/etc/caddy/Caddyfile`).
  Другие сайты на сервере не мешают: скрипт добавляет отдельный блок сайта и порт, который ещё не занят.
- Домен, указывающий на VPS (A-запись). Порты 80 и 443 должны быть открыты — Caddy получит сертификат сам.
- Приложение-аутентификатор на телефоне: Яндекс Ключ, Google Authenticator, Aegis и т. п.

## Установка (5 минут)

```bash
ssh vps
curl -fsSLO https://github.com/atomicpel/MyCheck-in/releases/download/server-N/install.sh
less install.sh          # по желанию: посмотреть, что делает скрипт
sudo bash install.sh
```

`server-N` — последний выпуск на странице Releases. Другой домен: `sudo DOMAIN=sim.example.ru bash install.sh`.

Скрипт:
1. скачивает программу для вашей архитектуры и сверяет контрольные суммы (SHA256SUMS);
2. создаёт системного пользователя `simvault` без входа в систему и папку `/var/lib/simvault` (права 700);
3. ставит службу systemd с жёсткой изоляцией: служба может писать только в свою папку и **не может
   сама соединяться с интернетом** — только принимать запросы от Caddy на 127.0.0.1;
4. включает ежедневную резервную копию в `/var/backups/simvault` (хранится 14 последних, права 600);
5. добавляет сайт в Caddyfile (копию старого файла сохраняет рядом), проверяет конфигурацию
   и перезагружает Caddy. Если Caddy не принял конфигурацию — возвращает старую.

При первом запуске скрипт **один раз** показывает:
- **ключ TOTP** — добавьте его в приложение-аутентификатор;
- **токен первичной настройки** — одноразовый, нужен, чтобы создать хранилище.

Не пересылайте их в мессенджерах и не делайте скриншот в облако.

## Первый вход

1. Откройте `https://ваш-домен` в браузере.
2. Введите токен настройки и придумайте **мастер-пароль** (лучше фраза из 4–5 слов, от 12 символов).
   Мастер-пароль не знает никто, даже сервер. **Если его забыть — данные не восстановить.** Запишите его на бумаге
   и храните отдельно.
3. Войдите: мастер-пароль и 6-значный код из аутентификатора.

## Подключение телефона

Приложение → меню → **Настройки** → «Сервер „Учёт SIM“» → адрес → **Подключить** →
мастер-пароль и код. Телефон станет доверенным устройством на 90 дней и сам отправит все карточки
и фото (зашифрованными). Дальше синхронизация идёт сама: при открытии списка, после сохранения
карточки и после загрузки из МТС.

## Обслуживание

| Задача | Команда |
|---|---|
| Обновить программу | снова `sudo bash install.sh` из нового выпуска (данные не трогаются) |
| Состояние службы | `systemctl status simvault` |
| Журнал службы | `journalctl -u simvault -n 50` |
| Журнал входов и действий | в веб-версии: значок часов; на сервере — `/var/lib/simvault/audit.log` |
| Отозвать все устройства | `sudo -u simvault /opt/simvault/simvault revoke-devices -data /var/lib/simvault && sudo systemctl restart simvault` |
| Новый ключ TOTP (потерян телефон) | `sudo -u simvault /opt/simvault/simvault reset-totp -data /var/lib/simvault && sudo systemctl restart simvault` |
| Резервная копия сейчас | `sudo systemctl start simvault-backup` |
| Восстановить из копии | `sudo systemctl stop simvault`, распаковать архив в `/var/lib/simvault`, `sudo chown -R simvault: /var/lib/simvault`, `sudo systemctl start simvault` |

Копии в `/var/backups/simvault` содержат зашифрованные записи и файл `config.json` с секретом TOTP.
Если копируете их на другой компьютер — храните там же надёжно, как ключи.

## Если что-то пошло не так

- **«Слишком много попыток»** — сработала защита от подбора: подождите 15 минут (или час, если ошибок было много).
- **Телефон пишет «отключён на сервере»** — устройство отозвано или прошло 90 дней. Подключитесь заново.
- **Сменили мастер-пароль** — все устройства и сессии отзываются автоматически; телефон нужно подключить заново.
- **Сертификат не выдаётся** — проверьте, что домен указывает на VPS и порты 80/443 открыты: `journalctl -u caddy -n 50`.
