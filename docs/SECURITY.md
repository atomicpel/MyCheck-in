# Безопасность «Учёт SIM»: сервер, веб-версия и приложение

Здесь хранятся паспортные данные. Цель — чтобы они не могли утечь ни при взломе сервера,
ни при краже резервной копии, ни при перехвате трафика.

## Главный принцип: сквозное шифрование (zero-knowledge)

Сервер хранит **только шифротекст** и **не знает ключа**. Расшифровать данные можно только
на устройстве пользователя (телефон или браузер) после ввода мастер-пароля.

| Что получает злоумышленник | Что он может прочитать |
|---|---|
| Полный доступ к VPS, база, резервные копии | Ничего из паспортов, ФИО, номеров. Только число записей, их размер и время изменения |
| Перехват трафика | Ничего (TLS 1.2+/1.3 через Caddy, HSTS) |
| Украденный пароль без второго фактора | Не войдёт: нужен код TOTP |
| Подбор пароля через сервер | Блокировка: 5 ошибок с адреса за 15 мин, 20 ошибок всего за час |
| Подбор мастер-пароля по украденной базе | PBKDF2-SHA256, 600 000 итераций на каждую попытку; при длинном пароле — нереально |

Чего сквозное шифрование **не защищает** (честно):
- взломанное устройство пользователя (вредоносное ПО на телефоне/компьютере видит то, что видит пользователь);
- веб-версию, если злоумышленник управляет сервером и подменит её код (так устроен любой веб-клиент;
  приложение на телефоне от этого не зависит — его код не загружается с сервера);
- забытый мастер-пароль: восстановить данные невозможно никому, включая администратора.

## Ключи

```
мастер-пароль ──PBKDF2-HMAC-SHA256(salt 16 байт, 600 000 итераций)──▶ masterKey (32 байта)
masterKey ──HKDF-SHA256(info "simvault-auth-v1")──▶ authKey  → отправляется серверу для входа
masterKey ──HKDF-SHA256(info "simvault-kek-v1")───▶ kek      → никогда не покидает устройство
vaultKey = 32 случайных байта (создаётся один раз при настройке)
wrappedKey = AES-256-GCM(kek, vaultKey, aad "simvault-vaultkey-v1")   → хранится на сервере
```

- Пароль перед KDF нормализуется в Unicode NFC, кодировка UTF-8.
- HKDF: salt пустой (32 нулевых байта по RFC 5869), длина 32.
- Сервер хранит не authKey, а `HMAC-SHA256(pepper, authKey)` и сравнивает за постоянное время.
  pepper — 32 случайных байта в файле конфигурации сервера (права 600).
- Смена пароля перешифровывает только vaultKey (wrappedKey), записи не трогаются.

## Формат шифротекста

Каждая запись и каждое фото шифруются отдельно ключом vaultKey:

```
base64( iv[12] || AES-256-GCM(vaultKey, iv, plaintext, aad) )   // тег 16 байт в конце
aad для записи = "rec:" + id записи,  для фото = "blob:" + id фото
```

aad привязывает шифротекст к своему идентификатору: сервер не может незаметно подменить одну запись другой.
Идентификаторы — случайные UUID, в них нет номеров и ФИО.

Открытый текст записи — JSON:
`{"t":"sim", ...поля карточки...}`, `{"t":"contract", ...}`, `{"t":"mts-accounts", "accounts":[...]}`.

## Вход и сессии

1. Клиент запрашивает параметры KDF (`/api/v1/prelogin`), вычисляет authKey, отправляет его и код TOTP.
2. Сервер выдаёт токен сессии (32 случайных байта): бездействие — 30 минут, максимум — 12 часов.
3. Телефон может стать **доверенным устройством**: получает токен устройства на 90 дней
   (хранится в зашифрованном хранилище Android Keystore). Устройство можно отозвать.
4. Все входы, ошибки, блокировки и изменения пишутся в журнал аудита сервера.

## Сервер

- Go, только стандартная библиотека (нет сторонних зависимостей — нет атаки через цепочку поставок).
- Слушает только `127.0.0.1`; наружу — через Caddy с TLS и HSTS.
- Отдельный системный пользователь, systemd-изоляция: `ProtectSystem=strict`, `NoNewPrivileges`,
  `PrivateTmp`, `ProtectHome`, `MemoryDenyWriteExecute`, `RestrictAddressFamilies`, `SystemCallFilter` и др.
- Данные в `/var/lib/simvault` (700), записи — файлы, атомарная запись через rename.
- Заголовки: строгий CSP (`script-src 'self'`, без inline), `X-Frame-Options: DENY`, `Referrer-Policy: no-referrer`,
  `Cache-Control: no-store` для API, `Permissions-Policy`.
- Лимиты размеров: запись до 256 КБ, фото до 4 МБ, всего до 2 ГБ.

## Приложение на телефоне

- Блокировка входа отпечатком/лицом/PIN телефона (настраивается), автоблокировка в фоне.
- Запрет снимков экрана и превью в списке приложений (настраивается).
- Локальная база — в закрытой папке приложения, резервное копирование Android выключено.
- Логины МТС, ключ хранилища и токен устройства — в EncryptedSharedPreferences (Android Keystore).
- Запросы к МТС идут с телефона напрямую на api.mts.ru, сервер их не видит.

## Веб-версия

- Ключи только в памяти вкладки; перезагрузка или 15 минут бездействия — блокировка и стирание ключей.
- Никаких внешних скриптов, шрифтов и CDN: всё отдаёт сам сервер.
